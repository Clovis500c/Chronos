Everything tunable lives in `Config.lua`:

```lua title="Chronos/Config.lua"
return {
	HistoryDuration = 1, -- History of player positions kept in seconds
	SampleRate = 30, -- Number of states recorded per second
	MaxChronos = 0.3, -- Maximum time (in seconds) players can Chronos
	HitboxSize = Vector3.new(4, 5, 1), -- Size of the reconstructed hitbox
	MaxDistance = 500, -- Maximum ray length in studs
	Debug = false -- Enable debug prints
}
```

## MaxChronos is your anti-cheat

<Callout type="warn">
Without this clamp, a client could send a timestamp from five seconds ago and hit players who were standing there back then. Keep it tight. `0.3` already covers a 300ms ping, which is a bad connection.
</Callout>

Raising it makes the game more forgiving for laggy players and more exploitable at the same time. No value avoids both, so pick where on that line your game sits.

## HistoryDuration must exceed MaxChronos

`HistoryDuration` is how far back the log reaches. `MaxChronos` is how far back a request may ask. If the second is larger than the first, you're allowing requests for states you've already thrown away.

The defaults leave a comfortable margin, 1 second of history against 0.3 seconds of reach. Keep roughly that ratio if you change either.

## SampleRate

30 snapshots per second means one every 33ms.

<Accordions type="single">
<Accordion title="Why not sample every frame?">

Because your recording rate would follow the server's framerate. Healthy server at 60 FPS, 60 snapshots per second. Busy server at 25 FPS, 25 snapshots per second.

The resolution of your rewind would silently degrade exactly when the server is most loaded, during a big firefight, which is when players need the compensation most.

</Accordion>

<Accordion title="Why not sample faster than 30Hz?">

Roblox only replicates character positions a limited number of times per second. Sampling faster than that records the same position twice rather than new information, so you pay CPU and memory for duplicates.

And `GetState` already interpolates between snapshots, so the gaps are filled anyway. Doubling the rate does not double the accuracy.

</Accordion>

<Accordion title="How do I know what rate Roblox actually replicates at?">

Measure it. From a server script, compare the `HumanoidRootPart` position each `Heartbeat` and count how often it actually changes versus how many frames elapsed.

Run it through **Test → Clients and Servers**, not a solo playtest. In solo, server and client are the same machine and you'll measure your own framerate instead of a replication rate.

</Accordion>
</Accordions>

## Debug

Turns on two prints, one on `Start` and one on `Stop`. Nothing else, so it won't flood your output during play.
