title: Limitations
description: What Chronos does not do, and prior art that does more.
---

Worth knowing before you use this.

## One hitbox per player

Only the `HumanoidRootPart` is tracked, so there's no headshot detection or limb-accurate hits. The hitbox size is a rough approximation of a character.

## Parts are created per shot

`ValidateHit` spawns and destroys Instances on every call. Fine for normal fire rates, not ideal for high volumes. An OBB intersection test would avoid this entirely, but it's out of scope here.

## NPCs aren't tracked

Only `Players` are recorded. Anything else in your game is invisible to the rewind.

## The offset stacks

Roblox already interpolates replicated characters, so the position the server sees is itself slightly behind reality. The rewind stacks on top of an existing offset.

## Victims can be hit after taking cover

On their own screen, a player can duck behind a wall and still take the hit, because the server validated a shot against the past.

This is inherent to lag compensation, not a bug. Every competitive shooter makes the same tradeoff: either the shooter's aim is wrong, or the victim's cover is late. There's no third option — the two players don't share a present moment.
