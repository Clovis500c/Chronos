Chronos records player positions over time, rewinds to the moment a shot was fired, and validates the hit against that past state.

Pure Luau. No dependencies, server only.

## The problem

Your screen always lies. What you see of another player is where they were a few frames ago, because the information took time to reach you.

<Tabs items={['On your screen', 'On the server']}>
  <Tab value="On your screen">
    You aim perfectly at their head, you fire, it's a clean hit. Everything about the moment says you connected.
  </Tab>
  <Tab value="On the server">
    At that same instant they've already moved a meter away. Your ray goes through empty space and nothing registers.
  </Tab>
</Tabs>

That's the "I hit them but nothing happened" feeling in badly networked games. Chronos closes the gap by judging the shot against the world the shooter actually saw.

## Install

<Steps>
<Step>

### Get the module

Download `Chronos.rbxm` from [Releases](https://github.com/Clovis500c/Chronos/releases) and drag it into Studio, or copy `src/` by hand.

<Files>
  <Folder name="Chronos" defaultOpen>
    <File name="init.lua" />
    <File name="Config.lua" />
    <File name="Types.lua" />
  </Folder>
</Files>

</Step>

<Step>

### Put it somewhere server-only

`ServerStorage` or `ServerScriptService`. Chronos refuses to run on the client — it warns and returns.

</Step>

<Step>

### Start recording

```lua
local Chronos = require(game.ServerStorage.Chronos)

Chronos:Start()
```

That's it. The position log fills up from the next frame onward.

</Step>
</Steps>

## Quick start

A complete round trip: the client sends when it fired, the server rewinds and applies damage.

<Tabs items={['Server', 'Client']}>
<Tab value="Server">

```lua title="ServerScriptService/Combat.server.lua"
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local ServerStorage = game:GetService("ServerStorage")

local Chronos = require(ServerStorage.Chronos)
local ShootRemote = ReplicatedStorage.Shoot

Chronos:Start()

ShootRemote.OnServerEvent:Connect(function(Player, ClientTime, Origin, Direction)
	if not Chronos:IsTimeValid(ClientTime) then
		return
	end

	local Hit = Chronos:ValidateHit(Player, Origin, Direction, ClientTime)

	if Hit then
		local Humanoid = Hit.Character and Hit.Character:FindFirstChild("Humanoid")
		if Humanoid then
			Humanoid:TakeDamage(25)
		end
	end
end)
```

</Tab>
<Tab value="Client">

```lua title="StarterPlayerScripts/Shooting.client.lua"
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local UserInputService = game:GetService("UserInputService")

local ShootRemote = ReplicatedStorage.Shoot
local Camera = workspace.CurrentCamera

UserInputService.InputBegan:Connect(function(Input, Processed)
	if Processed or Input.UserInputType ~= Enum.UserInputType.MouseButton1 then
		return
	end

	local Mouse = UserInputService:GetMouseLocation()
	local Ray = Camera:ViewportPointToRay(Mouse.X, Mouse.Y)

	ShootRemote:FireServer(workspace:GetServerTimeNow(), Ray.Origin, Ray.Direction)
end)
```

</Tab>
</Tabs>

<Callout type="warn" title="Use the right clock">
The timestamp **must** come from `workspace:GetServerTimeNow()`. It's the only clock that reads the same on both sides. `tick()`, `os.time()` and `os.clock()` all measure local machine time and will produce wrong results.
</Callout>

## Common questions

<Accordions type="single">
<Accordion title="Do I need to call Chronos.new()?">

No. The module returns a ready-made instance — `require` it and call methods directly. One recorder per server is what you want.

</Accordion>

<Accordion title="What happens if a player has 400ms ping?">

`IsTimeValid` rejects their shot, because 400ms is beyond the default `MaxChronos` of 0.3s. If you'd rather not punish them for a bad connection, use `GetSafeDelay` instead — it clamps the rewind rather than refusing the shot. See the [API reference](/docs/api).

</Accordion>

<Accordion title="Does this work with NPCs?">

Not as-is. Only `Players` are recorded. See [Limitations](/docs/limitations).

</Accordion>

<Accordion title="Can a cheater send a fake timestamp?">

They can send anything, which is why the timestamp is never trusted. `MaxChronos` caps how far back any request can reach, so the worst a spoofed time gets is 0.3 seconds of rewind — the same window an honest laggy player gets.

</Accordion>
</Accordions>
